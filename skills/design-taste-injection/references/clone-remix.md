# Clone Remix Route

Use this route only after the user approves a `verified-live` reference and chooses clone remix. The purpose is measured learning and adaptation, not passing off another site as original work.

## Guardrails

- Do not clone login, checkout, wallet, banking, identity, or other impersonation-sensitive pages.
- Do not ship source logos, copy, people, product imagery, analytics, API endpoints, or licensed fonts.
- Preserve structural or interaction ideas only when they fit the approved project requirements.
- Label confirmed runtime evidence, observed behavior, and inference separately.
- If access, bot protection, authentication, or unstable rendering prevents reliable measurement, return to the original path.

## Process

1. Measure the live page at desktop, tablet, and mobile. Capture computed tokens, section geometry, motion triggers, and DOM versus canvas/video surfaces.
2. Build or recover a stable local shell and verify it against the measured source.
3. Remove source identity and content before creative work.
4. Tokenize the shell. The vendored `tokenize-css.js`, `apply-overrides.js`, and `tweak-panel.js` are pinned MIT mechanics from `cth9191/site-clone`; read `vendor/site-clone-remix/UPSTREAM.md` before using them.
5. Apply the approved project information architecture, copy, brand, assets, reference set, and category constitution.
6. Create the `R` lineage in the main Design Workbench rather than a separate direction gallery.
7. Compare `O` and `R` when both exist. State what remains structurally indebted to the source.

The user’s chosen amplitude controls change depth:

- **Subtle:** palette, accent, motion timing, and effect colors.
- **Medium:** also surface, density, spacing, type scale, weights, and texture. Default.
- **Big:** also hero treatment, layout, section order, navigation style, and generated assets.

All variation layers must be reversible and scoped. Never destructively edit the only accepted base while exploring alternatives.
