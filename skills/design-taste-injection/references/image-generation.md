# Image Generation

Generate only after the user approves the direction, complete-homepage variant, eligible build path, and anchor-controlled H0 shell. Codex image generation is the default. Higgsfield is optional only when project-installed, authenticated, and selected by the user.

## Canonical recipe

The selected card's `imageRecipe` is canonical. Do not prepend a project subject or category constitution and do not create a competing recipe.

Maintain this semantic order:

1. Subject class and visual role.
2. Geometry and crop.
3. Placement and protected HTML regions.
4. Palette.
5. Lighting or flat treatment.
6. Material and texture.
7. Exclusions.

Existing compliant wording remains unchanged. Only separately reviewed catalog maintenance may materially change a recipe. Provider-specific technical parameters may follow the recipe without reinterpreting it.

For `kind:none`, the reviewed reason is the instruction: build the visual in code when code-native, or use/reserve authorized real media when required. Do not generate a substitute for protected products, artwork, people, portfolios, packaging, or interfaces.

## Reference and identity

Give the model the selected still and explicitly require inspection. Match visual relationships and feel, not source content or identity. Exclude curated source names, marks, copy, claims, people, products, characters, interfaces, and assets. Keep meaningful text and controls in HTML. A `codex-drafted` inventory is a generation guardrail, not independent human, legal, or QA review.

Never provide a motion clip or extracted frames. Never provide project intake, brand colors, industry, audience, other cards, the catalog, or category profiles.

## Output

For `primary` or `supporting`, generate exactly four distinct 2K images in one batch. Name their page states H1-H4, preserve H0, and show all five together. Each alternative receives its own provider receipt, recipe fingerprint, and asset SHA-256. A `TRY ANOTHER` request creates a new four-image batch and supersedes rather than deletes the prior batch.

Generated alternatives inherit H0 geometry and the frozen anchor system. Keep the media inside `data-future-image-slot`, mark it `data-generated-hero-media`, and do not change surrounding HTML, protected copy, typography, navigation, spacing, or responsive behavior. Run `visual-contract.mjs fingerprint-layout` at 1440, 768, and 390 pixels; every H1-H4 page must match the approved shell outside the media.

For `kind:none`, never invoke ImageGen. Record the reviewed code-native H0 or owned-media route as `H0-retained` with provider `none` and no generated asset receipt.

Generated visuals are new project assets, never evidence about the source. Run intake-leak and source-identity scans before import and require human review for ambiguous visual resemblance.
