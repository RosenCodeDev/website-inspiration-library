# Image Generation

Generate only after the user approves the anchor-controlled H0 composition. Codex image generation is the default. Higgsfield is optional only when project-installed, authenticated, and selected by the user.

## Canonical recipe

The selected card's `imageRecipe` is canonical. Do not prepend a project subject or category constitution and do not create a competing recipe.

Maintain this semantic order:

1. Subject class and visual role.
2. Geometry and crop.
3. Placement and protected HTML regions.
4. Palette.
5. Lighting or flat treatment.
6. Material and texture.
7. Exclusions.

Existing compliant wording remains unchanged. Only separately reviewed catalog maintenance may materially change a recipe. Provider-specific technical parameters may follow the recipe without reinterpreting it.

For `kind:none`, the reviewed reason is the instruction: build the visual in code when code-native, or use/reserve authorized real media when required. Do not generate a substitute for protected products, artwork, people, portfolios, packaging, or interfaces.

## Reference and identity

Give the model the selected still and explicitly require inspection. Match visual relationships and feel, not source content or identity. Exclude curated source names, marks, copy, claims, people, products, characters, interfaces, and assets. Keep meaningful text and controls in HTML. A `codex-drafted` inventory is a generation guardrail, not independent human, legal, or QA review.

Never provide a motion clip or extracted frames. Never provide project intake, brand colors, industry, audience, other cards, the catalog, or category profiles.

## Output

Generated alternatives inherit H0 geometry and the frozen anchor system. Preserve H0 in the workbench. Generated visuals are new project assets, never evidence about the source. Run intake-leak and source-identity scans before import and require human review for ambiguous visual resemblance.
